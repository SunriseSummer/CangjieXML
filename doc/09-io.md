# 09 — IO

包：`fastxml.io`

面向文件 / 字节流的 IO 边界封装——把"读取字节 + 解码 UTF-8"与"序列化 + 写盘"
收敛到一组顶层函数，错误分层清晰、与 Parser / Writer 的语法错误互不嵌套。

---

## 读取

### 顶层函数

```cangjie
public func loadXmlFromFile(path: String): XmlDocument
public func loadXmlFromFile(path: String, options: XmlParseOptions): XmlDocument

public func parseXmlBytes(bytes: Array<Byte>): XmlDocument
public func parseXmlBytes(bytes: Array<Byte>, options: XmlParseOptions): XmlDocument
```

- 文件一律按 **UTF-8** 解码；XML 声明的 `encoding="..."` 不参与实际解码。
- `parseXmlBytes` 用于 HTTP 响应体、JDBC BLOB 等"字节已在内存中"的场景。

### 错误映射

| 触发情形                       | 抛出                                                  |
| ------------------------------ | ----------------------------------------------------- |
| 文件不存在                     | `XmlIoException(FileNotFound(path))`                  |
| 文件读取失败（FS 异常）        | `XmlIoException(FileReadFailed(path, cause))`         |
| 字节不是合法 UTF-8             | `XmlIoException(FileReadFailed(path, "invalid UTF-8: ...") )` |
| XML 语法错误                   | `XmlParseException(...)`（**不**包装）               |

错误分层：`XmlIoException` 只负责 IO 边界；落盘之后的语法错误原样以
`XmlParseException` 抛出。

## 写入

### 顶层函数

```cangjie
public func saveXmlToFile(doc: XmlDocument, path: String): Unit
public func saveXmlToFile(doc: XmlDocument, path: String, options: XmlWriteOptions): Unit

public func writeXmlToBytes(doc: XmlDocument): Array<Byte>
public func writeXmlToBytes(doc: XmlDocument, options: XmlWriteOptions): Array<Byte>
```

### 实现选择：字符串暂存 vs 流式

- `saveXmlToFile` 的**默认实现是"字符串暂存 + 一次写盘"**：先 `writeToString`，
  再 `File.writeTo`。好处：若序列化过程抛异常，目标文件根本不会被打开，半成品
  不会落盘。
- 流式写盘可见下文 `FileXmlSink`，适合超大文档 / 边构造边写。

### 错误映射

| 触发情形                                  | 抛出                                                |
| ----------------------------------------- | --------------------------------------------------- |
| 写入失败（FS 异常：无权限 / 磁盘满…）     | `XmlIoException(FileWriteFailed(path, cause))`      |
| Writer 层异常（编码失败等）               | 原样抛出，不包装                                    |

---

## `FileXmlSink`：流式写盘

```cangjie
public class FileXmlSink <: XmlSink & Resource {
    public init(path: String)            // 目标文件若不存在则创建，若存在则截断

    public func write(text: String): Unit
    public func flush(): Unit
    public func isClosed(): Bool
    public func close(): Unit
}
```

实现 `Resource`，推荐用 `try (sink = FileXmlSink(...)) { ... }` 以保证 `close`
被调用：

```cangjie
try (sink = FileXmlSink("/tmp/big.xml")) {
    let w = XmlWriter(sink)
    w.writeDocument(doc)
}
```

### 资源语义

- `close` 会先 `flush` 缓冲区再关闭底层文件句柄；`flush` 失败也会尝试关闭文件，
  避免句柄泄漏。
- 流式模式的权衡：链路中间失败时，文件可能处于**半写入状态**。如果需要"全有
  或全无"，请改用 `saveXmlToFile`（字符串暂存）。

## 端到端示例

### Round-trip：构造 → 保存 → 读回

```cangjie
import fastxml.dom.*
import fastxml.io.*
import fastxml.build.*
import fastxml.query.*

let doc = XmlDocumentBuilder()
    .declaration()
    .root("catalog") { r =>
        r.element("book") { b =>
            b.attribute("id", "1").text("SICP")
        }
    }
    .build()

saveXmlToFile(doc, "/tmp/catalog.xml")
let loaded = loadXmlFromFile("/tmp/catalog.xml")

let root = loaded.rootElement.getOrThrow()
root.requiredChildElement("book").intAttribute("id")   // Some(1)
```

### 字节形态：解析 / 生成 HTTP body

```cangjie
// 服务端：把 DOM 序列化为 HTTP 响应字节
let bytes: Array<Byte> = writeXmlToBytes(doc)

// 客户端：从响应字节构造 DOM
let parsed = parseXmlBytes(bytes)
```

### 防御性错误处理

```cangjie
import fastxml.dom.*
import fastxml.io.*
import fastxml.error.*

let doc = try {
    loadXmlFromFile("/tmp/missing.xml")
} catch (e: XmlIoException) {
    match (e.error) {
        case FileNotFound(p) =>
            println("missing: ${p}")
            return 1
        case FileReadFailed(p, msg) =>
            println("read ${p}: ${msg}")
            return 1
        case _ => throw e
    }
} catch (e: XmlParseException) {
    println("parse error at ${e.error}")
    return 2
}
```

## `XmlIoException`

```cangjie
public class XmlIoException <: Exception {
    public let error: XmlError
    public init(error: XmlError)
    public override func getClassName(): String { "XmlIoException" }
}
```

与 `XmlParseException` 的分工：

| 异常                    | 职责                                    |
| ----------------------- | --------------------------------------- |
| `XmlIoException`        | IO 边界：文件不存在 / 磁盘错误 / 非法 UTF-8 |
| `XmlParseException`     | 语法错误：字节已读到、但 XML 不合法    |
| `XmlException`          | 程序员错误：DOM 不变量违反等            |

三者互不嵌套。
